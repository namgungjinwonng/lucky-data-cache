# LUCKY 45

역대 로또6/45 데이터를 분석해 점수 구간별로 분산한 20게임을 보여주는 Android 전용 앱입니다. 럭셔리 모터스포츠의 긴장감과 정밀함을 참고하되 특정 자동차 브랜드의 로고, 이미지, 서체는 사용하지 않습니다.

## 주요 기능

- 전체 빈도 21%, 최근 가중 빈도 24%, 번호 쌍 22%, 조합 형태 23%, 지난 회차 이월 10%를 결합한 패턴 점수
- 20·30·40·50·60·70점대 기본 1·3·6·6·3·1게임 배분에 최근 26회 당첨 점수 분포를 최대 20% 반영
- 추천 20게임 전체의 게임 쌍마다 공통 번호를 최대 2개로 제한
- 최신 당첨번호를 해당 회차 직전 데이터로 평가한 패턴 점수와 다음 회차 목표 비중·게임 수 표시
- 가상 균등 추첨에서 추가 당첨 기회를 넓히는 후보를 우선하고, 동점이면 번호 쏠림과 과거 패턴 점수로 선택
- 별도 워커에서 추천을 계산해 분석 중에도 화면과 탭을 조작할 수 있음
- 과거 하위·혼합 추천 이력은 보존하고, 아직 마감되지 않은 다음 회차만 새 구성으로 전환
- 다음 회차를 시드로 사용해 같은 회차에는 동일한 추천 결과 제공
- 1회부터 최신 회차까지 당첨번호와 1·2등 당첨 판매점 조회
- 현재 위치 기준 가까운 공식 로또 판매점 20곳과 역대 1·2등 당첨 횟수 표시
- 사용자가 선택하고 기기에 저장되는 라이트·다크 테마
- Kakao Maps 키가 있으면 Kakao 지도, 없거나 연결에 실패하면 OpenStreetMap 사용
- GitHub 원격 JSON을 통한 회차·당첨점·판매점 데이터 동기화
- 네트워크 장애 시 캐시 또는 APK 내장 데이터 사용
- GitHub Actions를 통한 주간 데이터 갱신과 APK 빌드

## 로컬 실행

```bash
npm ci
npm run dev
```

## 검증

```bash
npm run test:run
npm run build
```

## Android 동기화

```bash
npm run android:sync
```

APK는 GitHub Actions의 `Build Release APK` 실행 결과에서 `lucky-45-release-apk`를 내려받아 설치할 수 있습니다. Actions 실행 번호가 Android `versionCode`가 되므로 동일한 서명키로 만든 다음 버전을 기존 앱 위에 설치할 수 있습니다.

## Release APK 서명

GitHub Actions에는 아래 네 가지 Repository secret이 필요합니다. 서명키 원본과 비밀번호는 저장소에 커밋하지 않고 별도로 안전하게 백업해야 합니다. 서명키를 잃으면 기존 설치 앱을 업데이트할 수 없습니다.

- `ANDROID_KEYSTORE_BASE64`는 PKCS12 서명키 파일 전체를 Base64로 변환한 값입니다.
- `ANDROID_KEYSTORE_PASSWORD`는 키 저장소 비밀번호입니다.
- `ANDROID_KEY_ALIAS`는 서명키 별칭이며 기본값은 `lucky45`입니다.
- `ANDROID_KEY_PASSWORD`는 개별 키 비밀번호입니다.

## Kakao Maps 설정

Kakao Developers에서 앱을 만든 뒤 JavaScript 키를 발급하고 JavaScript SDK 도메인에 로컬 개발 주소와 Android WebView 주소를 등록합니다.

- 로컬 개발은 `http://127.0.0.1:5173`입니다.
- Android 앱은 Capacitor 기본 주소인 `https://localhost`입니다.
- 로컬에서는 `.env.example`을 `.env.local`로 복사한 뒤 `VITE_KAKAO_MAP_JAVASCRIPT_KEY`에 키를 입력합니다.
- GitHub Actions에서는 저장소의 Actions secret `KAKAO_MAP_JAVASCRIPT_KEY`에 같은 키를 등록합니다.

키를 설정하지 않아도 앱은 OpenStreetMap으로 정상 동작합니다.

## 데이터 흐름

추천 알고리즘 버전은 4입니다. 점수 정의는 버전 3 그대로이며 3만 무작위 후보의 평균을 50점, 표준편차를 12점으로 변환합니다. 고득점만 선택하지 않고 기본 구간 비율 80%와 최근 26회 당첨 점수 분포 20%를 합쳐 20게임을 최대 나머지 방식으로 정수 배분합니다. 26회 미만이면 최근 영향은 표본 수에 비례해 줄입니다. 번호별 빈도·번호 쌍·이월 계산에도 최신 당첨번호가 포함됩니다. 이 배분은 예측력 향상이 입증된 규칙을 의미하지 않습니다.

`src/core/pattern-seed.json`은 21~1247회의 사전 점수 캐시입니다. 각 회차 점수는 해당 회차를 제외한 이전 데이터로 계산하고, 해시는 대상 당첨번호를 포함한 전체 입력의 SHA-256입니다. 이전 데이터나 대상 번호가 수정되면 캐시가 무효화됩니다. 새 회차는 앱의 Web Worker에서 계산하고 기기에 최근 26회만 저장하므로 매주 APK를 바꿀 필요가 없습니다. 선택적으로 `node scripts/build-pattern-seed.mjs`로 캐시를 재생성할 수 있습니다. 점수 정의 자체를 바꿀 때에는 점수 버전·캐시 키를 올리고 시드도 재생성해야 합니다.

새 추천은 `구간` 분류로 저장합니다. 추천 이력은 알고 있는 최신 회차의 바로 다음 회차만 새로 저장하거나 버전을 올릴 수 있습니다. 기록 보존을 위해 다음 회차 날짜의 20시(KST)를 교체 마감으로 사용하므로, 오래된 오프라인 데이터로 지난 추천을 다시 쓰지 않습니다. 기존 상위·하위·혼합·분산 및 1,244회 기록은 그대로 보존합니다.

매주 일요일 00시와 일요일 05시 KST에 GitHub Actions가 동행복권의 공개 응답을 확인해 최신 회차, 역대 회차와 회차별 당첨 판매점을 갱신합니다. 자정에 새 회차를 1차 수집하고 새벽 5시에 한 번 더 확인합니다. 전국 판매점 목록은 28일마다 새로 확인합니다. 앱은 실행·화면 복귀 시와 화면이 켜진 동안 5분마다 GitHub 원격 JSON을 확인합니다. 최신 결과와 전체 회차 데이터의 갱신 시점이 다르면 추천을 잠시 숨기고 분석 데이터 갱신을 기다립니다.

- `public/data/history.json`은 1회부터 최신 회차까지의 당첨번호입니다.
- `data/winners/####.json`은 회차별 1·2등 당첨 판매점입니다.
- `public/data/stores.json`은 위치 계산과 판매점별 역대 1·2등 횟수 표시에 사용하는 전국 판매점입니다.

## 주의 사항

모든 6개 번호 조합의 실제 1등 확률은 `1 / 8,145,060`으로 같습니다. 앱의 점수는 과거 데이터와의 패턴 유사도이며 당첨확률을 높이거나 당첨을 보장하지 않습니다. 실제 당첨 여부와 판매점 영업 여부는 반드시 동행복권 공식 정보와 실물 복권으로 확인해야 합니다.
